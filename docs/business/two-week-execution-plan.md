# HMS Elite - Plan Ejecutivo de 2 Semanas

Fecha de referencia: 2026-03-10
Owner sugerido: CEO / Product / Principal Engineer
Estado: plan historico; la prioridad vigente se mantiene en [roadmap.md](roadmap.md) y [backlog.md](backlog.md)

## Objetivo
Cerrar una version vendible, demostrable e implementable sin improvisacion.

## Regla
Durante estas 2 semanas no abrir bloques nuevos grandes salvo defecto critico o requerimiento de venta real.

## Norte de estas 2 semanas
- validar el producto como experiencia real
- cerrar defects visibles y no seguir agregando UI por reflejo
- consolidar la demo comercial
- dejar el paquete comercial listo para usar con un cliente real

## Semana 1 - Validacion y cierre de producto

### Objetivo
Confirmar que HMS Elite ya se puede mostrar y operar con confianza.

### Bloques

#### 1. QA manual final
Owner:
- Product / QA / Principal Engineer

Tareas:
- ejecutar la checklist de QA manual por rol
- validar anchos `375`, `390`, `430`, `768`, `1024`, `1440`
- registrar defects reales

Entregable:
- corrida completa sobre [manual-qa-role-checklist.md](../validation/manual-qa-role-checklist.md)

#### 2. Correccion de defects puntuales
Owner:
- Engineering

Tareas:
- corregir defects de permisos
- corregir defects de drawers y sheets
- corregir defects responsive puntuales
- no abrir refactors grandes

Entregable:
- defects corregidos con evidencia PASS/FAIL

#### 3. Congelar discurso de producto
Owner:
- CEO / Product

Tareas:
- definir posicionamiento principal
- decidir segmento prioritario
- cerrar que HMS Elite se vende primero como PMS operativo serio para hotel mediano

Entregable:
- mensaje comercial principal validado

### Criterio de cierre de semana 1
- QA manual ejecutada
- defects visibles cerrados o priorizados
- demo operativa sin puntos vergonzosos
- segmento prioritario definido

## Semana 2 - Comercial y delivery listos para usar

### Objetivo
Salir con material y proceso comercial mas serios.

### Bloques

#### 1. Ensayo de demo comercial
Owner:
- CEO / Comercial / Product

Tareas:
- usar el caso mediano como recorrido principal
- ensayar apertura, demo, objeciones y cierre
- ajustar discurso si aparece ruido

Entregable:
- demo comercial repetible de 20 a 30 minutos

#### 2. Paquete comercial utilizable
Owner:
- CEO / Comercial

Tareas:
- usar matriz de decision
- usar playbook de segmento
- usar propuesta base correcta
- usar mail por segmento

Entregable:
- paquete listo para una oportunidad real:
  - deck
  - propuesta
  - SLA
  - condiciones
  - discovery notes

#### 3. Handover a implementacion
Owner:
- Product / Delivery / Engineering

Tareas:
- usar onboarding
- usar entregables
- usar bitacora de implementacion
- revisar go-live checklist

Entregable:
- camino claro desde cierre comercial hasta onboarding

### Criterio de cierre de semana 2
- existe una demo comercial repetible
- existe una propuesta por segmento lista para adaptar
- existe un proceso claro de handover a implementacion
- no depende de memoria o improvisacion

## Prioridad recomendada
1. hotel mediano
2. hotel chico
3. cadena / multi-hotel

## Lo que no hacer en estas 2 semanas
- no abrir features grandes nuevas
- no vender enterprise sin discovery
- no seguir puliendo UI si no hay defecto real
- no mandar pricing sin alcance

## Riesgos
- seguir agregando cosas y no cerrar nada
- querer vender todos los segmentos al mismo tiempo
- meter demasiada energia en deck visual sin validar demo y proceso
- usar materiales comerciales sin personalizacion minima

## Resultado esperado al final
- HMS Elite se puede mostrar con confianza
- HMS Elite se puede vender con criterio
- HMS Elite se puede implementar sin improvisacion

## Siguiente paso despues de estas 2 semanas
- billing mas profundo si la venta o el delivery lo exigen
- deck visual final con branding
- pipeline comercial simple en CRM o planilla
